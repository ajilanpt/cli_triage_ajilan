# Interview — phase 07

## What calibration changed
Predicted ECE would improve and AUC would stay the same. ECE and Brier both improved
(equal-frequency ECE: 0.048 -> 0.044; Brier: 0.044 -> 0.036), matching the prediction. AUC
did not stay the same -- it dropped, from 0.587 to 0.519, because `CalibratedClassifierCV`'s
internal cv=3 retrains the base model on only two-thirds of an already-small, unevenly
distributed fold's training data each time. Calibration bought better-shaped probabilities
at a real cost to ranking ability, on top of a signal that was already weak.

## What question the pivot answers
Not "does one model generalize cold to a project it has never seen a single row from"
(the original grouped-split question, answered weakly: 0.587 AUC, one fold at 0.121). The
pivot answers "given a project's own accumulated history, how well does a model trained on
that project's own data perform on more of that same project's data" -- per-project,
stratified k-fold within the project. Overall per-project AUC: 0.829 across the 17 projects
with enough positives to score.

## Which claim the new scope no longer supports
The system can no longer claim to work out of the box, cold, on a brand-new project with no
accumulated history -- that was the original claim implied by the grouped-split evaluation,
and it is not what the pivot measures. The honest claim after this phase is narrower: this
component becomes useful once a project has enough of its own labeled history (in practice,
at least ~5 flaky-labeled rows, per `MIN_POSITIVES_FOR_PER_PROJECT`), and the cold-start gap
for a project without that history is real, named, and unresolved (`knowns/07-tabular-and-
the-pivot.md`), not fixed by this pivot.
